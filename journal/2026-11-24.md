# 2026-11-24: Finishing the data layer, starting the universe

**Stage:** 1 finished, stage 2 started

## What happened

Yesterday I left the data stage half done. Today I wanted to finish it properly, and I did not want to only agree with the decisions. I wanted to make them myself. Before moving on, I went back over stages 0 and 1 once more and checked that each decision matched my own reasoning, not just the write-up.

## What I did

1. **Checked how stock splits change historical prices.** I picked three real days around large stock splits and compared the vendor's adjusted prices with the raw prices that actually traded. The adjusted series rewrites the past using a split that had not happened yet at the time. A backtest that sees adjusted prices is quietly using future information.
2. **Decided how to handle corporate actions point-in-time.** Prices stay raw. On the day of a split, only the previous close is converted before measuring the overnight move. Any multi-day measure is adjusted only for splits known up to that day, never for later ones.
3. **Separated cleaning from selection, again.** Cleaning only removes broken data. Odd prints that are real trades stay in the data, and I measure how often they happen instead of deleting them. Whether a stock is too thin to trade is decided at the moment of entry, using only the bars that have already happened.
4. **Fixed a caching bug myself.** When the download returned nothing for a day, the empty answer was saved, and that day was skipped forever after. I found 150 such files and deleted them. I then changed the code so that empty price data is never saved, while other empty answers (for example, no news that week) still are.
5. **Locked the fix in with a regression test.** I wrote a test for the new behavior, ran the full test suite, and then deliberately removed the fix to confirm that the test turns red without it. I also made the test run in a throwaway folder and delete it afterwards, so it never touches the real cache or leaves files behind.
6. **Started the universe stage.** I decided that stock selection must be fully mechanical, both in the backtest and live, so that the two test the same thing. I read the academic work on why some stocks move more than others on a given day, and wrote down a small set of candidate selection rules before looking at any result.

## What I learned

- **Split-adjusted prices are a form of look-ahead.** They are convenient for charting, but every adjusted price before a split was computed using information from after it.
- **A corporate action can carry information.** Some corporate actions tend to happen to companies in trouble. Using that information is fine only if I use it the way I would have known it on that day.
- **A test that has never failed has not been tested.** The useful check was not "the tests are green". It was removing the fix and watching the new test catch the bug.
- **Tests must not change the world they run in.** My first version of the test left a temporary folder behind every time it ran. Small leaks like that pile up quietly.
- **Research goes upstream first.** Which stocks I trade changes every result downstream of it. So the selection rule is chosen first, averaged across all the exit variants, and only then are the exit variants compared.
- **Split the data before looking at it.** One period for development, one for validation, and one held back and opened only once at the end. Some of the most recent data has already been seen in earlier work, and I am noting that instead of pretending it is untouched.

## Decisions

- Data: raw prices, with corporate actions applied point-in-time; cleaning removes only broken data; empty downloads are never cached.
- Thin trading is judged at the moment of entry, with information available at that moment.
- Stock selection is fully mechanical, in the backtest and live.
- Selection candidates are pre-registered as a small set and compared on the development data first.
- Data split: development, validation, and a final hold-out opened once.
